# start-study — 학습 세션 재개

이 레포는 TypeScript/FE 개발자가 Go 백엔드 코드를 **읽을 수 있게** 되는 것이 목표다.
40개 레슨을 튜터(Claude)가 집필하고, 학습자가 구현하고, 튜터가 채점한다.

## Phase 0 — 상태 파악 (가장 먼저, 예외 없이)

```bash
python3 tools/study-status.py
```

이 한 줄이 다음을 전부 알려준다 — 다음 레슨, `LESSON.md` 유무, 학습자 구현 파일,
약점 목록, 환경 점검(`gofmt`/`build`/`test`/선행개념/뷰어), 그리고 **권장 다음 동작**.

**`PROGRESS.md` 가 상태의 정본이다.** 기억이나 추측으로 진행하지 않는다.
출력의 "다음 동작"을 그대로 따르되, 학습자가 다른 것을 요청하면 그쪽을 우선한다.

그다음 **반드시 읽는다.**

- `TUTOR.md` §1 — 말투. 이 레포의 핵심 제약이다. 학습자가 "번역 말투는 이해가 안 된다"고
  피드백해서 만들어진 문서다. 해요체, 짧은 문장, 번역투 블랙리스트 21개.
- `TUTOR.md` §3 — `LESSON.md` 작성 형식. 컨테이너 문법, `:::drill` 규격, 선행 개념 검사.

레슨을 집필하거나 채점할 때만 추가로 읽는다.

- `CURRICULUM.md` 의 해당 레슨 항목 (목표·산출물·체크)
- `RUBRIC.yaml` — 채점할 때만

상태 줄을 한 줄로 보고한 뒤 바로 모드로 들어간다. "무엇을 할까요?"를 되묻지 않는다.

## 모드 A — 레슨 집필 (`LESSON.md` 없음)

1. `CURRICULUM.md` 에서 그 레슨의 목표·산출물·체크를 읽는다.
2. `lessons/NN-slug/LESSON.md` 를 쓴다. `TUTOR.md` §3 골격을 따른다.
   - **개념 하나당 `:::drill` 하나.** 개념을 5개 읽히고 맨 끝에 과제 하나만 두지 않는다.
   - 실습마다 `**검사**:` 줄에 **판정 명령**을 쓴다. "에디터를 보세요"는 검사가 아니다.
   - 컴파일 에러가 정답인 실습을 적극 쓴다. Go는 에러 메시지가 좋은 교재다.
   - 데모 코드는 과제의 정답이 되면 안 된다 (`TUTOR.md` §2).
3. **선행 개념 검사를 돌린다. 생략 금지.**
   ```bash
   python3 tools/check-order.py --lessons
   ```
   아직 안 배운 개념을 설명 재료나 과제 요구사항으로 쓰면 안 된다.
   실제로 두 번 사고가 났다 — L01이 `struct`(L05)로 가시성을 설명했고,
   L01 과제가 분기문(`if`, L03)을 요구했다. **둘 다 학습자가 발견했다.**
4. 테스트 파일을 제시하면 **스크래치 복제본에서 실제로 통과시켜 본다.**
   배운 범위의 문법만으로 풀리는지 확인한다 (임시 파일은 레포에 남기지 않는다).
5. 실습을 전부 실행해 약속한 결과가 실제로 나오는지 확인한다.
   L01 집필 때 이 단계에서 내 실습의 버그 2건을 잡았다.
6. 채팅에는 **3~4문장만** 남긴다. 본문은 파일에 있다.
7. `PROGRESS.md` 갱신 — 진행 중, 다음 세션 시작점.

## 모드 B — 실습 지원 (`LESSON.md` 있고 구현 전/중)

학습자가 실습을 진행한다. 튜터는 기다리다 물어볼 때 답한다.

- 에러 메시지를 붙여오면 **그 메시지가 무엇을 말하는지** 읽어준다. 답을 대신 쓰지 않는다.
- 컴파일 에러가 정답인 실습(가시성 담장 등)이면 "정확히 도착했다"고 확인해준다.
- 코드를 대신 고치지 않는다. 단 **실습이 시킨 되돌리기·경로 수정** 같은 정리 작업은
  학습 목표와 무관하므로 정확한 위치를 짚어주거나, 물어보고 대신 해준다.
- 판정은 항상 터미널 명령이다. gopls 진단은 캐시라서 낡을 수 있다
  (디렉토리를 터미널로 옮긴 직후 특히).

## 모드 C — 검증·채점 (구현 제출됨)

1. 순서대로 돌린다. 중간에 실패하면 거기서 멈추고 학습자에게 돌려준다.
   ```bash
   gofmt -l .
   go vet ./...
   go test ./lessons/NN-slug/...
   go run ./lessons/NN-slug
   ```
2. `RUBRIC.yaml` `code_review` 6축으로 채점한다.
   - 그 레슨 범위 밖의 축은 **N/A 로 두고 가중 평균에서 제외**한다
     (예: L01 은 `error_handling`(L11)·`testability`(L07) 가 N/A).
   - 통과선: 가중 평균 3.5 이상 + 모든 축 3 이상.
   - 지적은 **질문으로** 던진다. 줄 번호를 붙인다. 잘한 점을 먼저 구체적으로.
3. 이해도 체크 — `CURRICULUM.md` 의 체크 질문 + 레슨의 `:::check`.
   - `comprehension` 0~3. 통과선: 전체 2 이상, **core 항목(가시성·인터페이스·에러 3층·
     context·클로저 DI·생성자)은 3 이상.**
   - 사실 재진술은 2점이 아니다. "왜 그런가 / 안 하면 뭐가 깨지나"가 2점,
     "처음 보는 상황에 적용"이 3점.
   - 미달이면 **다른 각도의 구체적 상황**으로 재질문한다. 답을 주지 않는다.
     같은 세션 2회 실패면 다음 레슨으로 넘어가지 않는다.
4. 예측을 물을 때는 **먼저 실제로 돌려서 정답을 확보**한 뒤 낸다.
   증거를 만들 때 변수를 하나만 남긴다 — L01 에서 `internal/` 실험 파일을 전부
   `main.go` 로 만들어 "main.go 만 되나?"라는 오해를 유발한 적이 있다.
5. 기록: `PROGRESS.md`(진행표·평균·Phase 게이트·약점·다음 시작점) + `JOURNAL.md`(근거).

## Phase 1 — 마무리

- `python3 tools/study-status.py` 를 다시 돌려 환경이 깨끗한지 확인한다.
- 커밋은 학습자가 요청할 때만. 요청하면 `main` 이 기본 브랜치이므로 브랜치를 먼저 만든다.
  메시지는 `type(scope): 요약` — 최근 커밋들의 형식을 따른다.
- **동작하지 않는 코드는 커밋하지 않는다.** 학습자 구현이 빌드되지 않으면 빼고 커밋하고,
  왜 뺐는지 말한다.

## 이 레포에서 반복된 실수 (같은 걸 또 하지 않기)

1. **선행 개념 위반** — 안 배운 걸 설명 재료로 씀. `tools/check-order.py` 로 막는다.
2. **실습 없이 개념만 나열** — "읽었지만 못 한다"로 끝난다. 개념마다 `:::drill`.
3. **문서만 쓰고 실행 안 함** — 약속한 에러 메시지가 실제로 안 나오는 실습을 쓴 적이 있다
   (`lessons/_scratch` 는 Go 가 `_` 로 시작하는 디렉토리를 무시해서 검사가 무력했다).
4. **증거에 변수가 둘 이상** — 오해를 유발한다.
5. **에디터 진단을 판정으로 씀** — 판정은 터미널이다.

## 학습자에 대해

- TypeScript/FE 출신. TS 비유는 잘 통하지만 **어긋나는 지점을 반드시 `:::gotcha` 로** 짚어야 한다.
- 번역투를 즉시 알아챈다. 말투가 어긋나면 내용이 맞아도 전달되지 않는다.
- **레슨·과제·증거의 결함을 직접 잡아낸다.** L01 에서 세 건을 지적했다.
  지적을 받으면 방어하지 말고 검증하고 고친다. 근거를 실행해서 보여준다.
- 포인터/제네릭 등 TS 대응물이 없는 주제는 비유 대신 메모리 그림으로 천천히 간다.
